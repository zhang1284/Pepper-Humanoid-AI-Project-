# Pepper research documentation

Research goal: build a team-owned Pepper application that meets the useful baseline of RoboHearts and extends it with document context, vision, tablet content, gestures, and dependable navigation. The intended Harper pilot places Pepper beside the second-floor welcome desk and eventually validates the triangular route around that floor.

## Reading the evidence

Historical notes retain the findings and pending work from the day they were written. Later dated corrections in the chronological record take precedence. The capability matrix is an investigation history, not a fully current certification. A command acknowledgment, a successful build, and an observed physical outcome are distinct evidence.

The report references paths in the original research workspace. Only the documentation is shared in this update; the source code, verification data, and robot artifacts at those paths are not all present in this repository.

## Scope and handling

These notes are a documentation snapshot. Local network addresses and personal absolute file paths in the historical notes have been replaced with placeholders. API keys, passwords, environment files, raw participant media, private map archives, Android build tools, and APKs are not included. The original notebook and its README are preserved.

## Session close updates

At the end of a research session, update the chronological record, add a dated summary with observed results and open questions, and revise the limitations report when evidence changes a finding. Review the exact documentation diff, then publish using an authenticated account with repository write permission. Follow the repository's branch rules; use a pull request if direct updates are not allowed. This is a session workflow, not an unattended background synchronization service.
